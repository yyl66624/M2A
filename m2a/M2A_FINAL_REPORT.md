## 5 创新点（分级，按证据强度）

### I1（最强）：**省略 = S 层 ⊕ C 层的合取**

- **内容**：选择性不响应（S）无需表征；"省略"作为一等机制还要求**反事实可及性表征**（C）——系统把被跳过的选项表示为"可用且可评估"。
- **证据**：21 条全文（物理化学的 S 层实例 6 条；表征系统的 C 层实例）＋ E2（构造性）＋ L3（定量：敏感度随证据量线性上升）。
- **新颖性**：介于**新定义**与**新假说**之间。Day 1 文献里"省略/弃权"没有这个分层；但"表征是反事实推理前提"本身不是新思想。
- **可证伪**：若存在无表征却对"可用性"敏感的系统 ⇒ 假说被否证。

### I2（中 → 中上）：**合取窗口的分位差律 `β ≥ q_{1−α}(F) − q_α(F)`**

- **内容**：合取不是"标签"，而是一个有**增益门槛**的机制：增益不足时，任何阈值都无法同时做到单路静默与双路点火；
  门槛的数值由**噪声分布的分位差**给出。
- **证据**：解析推导 + 蒙特卡洛（5 个 β）+ **三个独立基底**（logistic 5.889 / probit 3.290 / Gumbel 4.067，
  数值复现误差 ≤0.002）。
- **诚实定位**：单基底时是初等代数；**跨基底**后升级为"形式与分布无关、常数可预测"的条件——
  仍不是经验发现，但已不是参数化巧合。

### I3（方法学）：**触发/门的可测签名**

- **内容**：触发 = 单向单调；门 = 符号可翻转（由开放度相对 0.5 决定）；约束 = 饱和。
- **证据**：E1b + L2。
- **用途**：把跨域机制比较从"类比"推进到"同一组可测签名"，直接服务 M2A 的桥接判据（B-01/B-04 目前是 ANALOGY-ONLY）。

### I4（负结果，同等重要）：**K4 的覆盖缺口是结构性的**

- 补入 7 条后覆盖仍 3/8；新增全部落在 G3/G4。⇒ 这不是检索失败，而是文献分布本身。

### 10.1 对 §4.1 与 §2.3 的更正（L3 归因方向反转）

§4.1 末行原写"Phase III 的残余偏差归因于学习器，而非律"。Phase V 的精确算子给出相反方向：

```
0.36(2q−1)  ──先验 1/2 → 2/5──►  状态层律  ──访问加权──►  w(p)=2p/(3−p) 的闭式
q=0.8:  0.2160  ──►  0.2104  ──►  0.1944  = DP(1.4e-13 内) ≈ MC 0.1945
```

⇒ **残差住在解析律的条件先验与探针的访问加权里，学习器精确收敛到自身算子的不动点**。
并且 `p4_mechanisms.bayes_sensitivity` 用 `rng.rand() < 0.5` 抽样 B 可用性，与律**共用先验**，
所以"独立估计器与律逐格精确一致"不构成对先验的独立检验（该支实测 q=0.8 给 0.2140）。
证据分级修正：L3 的"中强（模拟中段有 ~0.02 系统偏差，未解释）"应读作
**"律的条件先验写错，修正后与精确算子在 1e-13 内一致"**。

```
β*(T, k, m, s) = ( q_φ − q_ψ ) / ( 1 − L(T,m,s) ),   φ=(1−α)^{1/k},  ψ=α/(1−α)^{(k−1)/k}
```

#### 35.2 三套措辞、三份承载工件

补全不能只把正则式加宽：文献侧写的不是「关闭/落实」，而是「待裁定/建议/需指定/未覆盖」，

1. **每个命名空间有自己的措辞类别**（`CLASS_NS`），实验轮的三个正则一字未动；
2. **每个命名空间有自己的承载判定措辞的工件**：`L01-O*` 只看 `ROUND_L01_RESULTS.md`，
   `O-*` 只看 `08_OPEN_QUESTIONS.md`（owner 2026-10-18 明示「`O-01…O-15` 的状态字保持原样」）。
   其他文件的提及**计入证据与漂移检测，但不得翻转状态**——与负面日志不参与判定（X-67）是同一条规则；
3. **状态文件里以「条目」为判定窗口**（一个 bullet/编号项连同它的续行），因为这两份文档把一条

#### 40.1 方法（相对 §39 四处收紧）

1. **注入量级改为相对 1e-4**。§39 用的 1e-8 绝对偏移依赖「注册容差是 1e-12」这一巧合；跨 13 个模块后
   量纲不齐（分位数是「个计数」、β\* 是 O(10)、水平是 O(0.5)），故统一为相对偏移。1e-4 比最松的注册
   锚点容差（1e-9 相对、1e-15、逐位相等）大 1e5 倍，又比本轮任何可能被误解释的**效应**量级小
   （最小效应 1.25e-3，J=800），所以拒绝的含义是「门控盯着已提交读数」而不是「门控盯着一个坏程序」。
2. **拒绝的定义收紧**：退出码非 0 **且**至少打印一条 `FAIL` 检查名。§39 的判据是 `rc != 0`，
   于是**变异把被测程序改崩**也会被记成「门控拒绝了」——那是审计仪器自己的洞（X-77）。
   收紧后五台旧目标逐一复核：它们都打印了具名 FAIL（G4、G3、P6c 等），故 §39 的结论一字不改。
3. **加两条前置控制**：(i) 变异后的模块必须仍能 `import`（R1.1 那一类 NameError/语法错）；
   (ii) 变异必须**确实改变一次探针读数**——同一表达式分别在未变异副本与变异副本里求值，逐字符比对。
   若两值相同，则这次注入是空操作，门控的答复作废（既不能算拒绝也不能算盲）。
   这条控制是 R8 的反身应用：**没改变任何东西的变异不构成关于门控的证据，只构成关于探针的证据**。
4. **区分「仪器侧」与「主张侧」变异**（R2）。前者污染量具（网格、求根、尾指标、聚合算子、被测量定义），
   门控必须拒绝；后者改变这一轮要检验的那个量（Phase XI 的解析 β\* 律），门控**不该**拒绝——
   拒绝了就等于量具在替科学判据背书，正是 R2 禁止的事。主张侧的保障在别处：
   读数冻结在已提交的结果 JSON 里，其字节被预注册哈希绑定，改它表现为**绑定断裂**而非门控失败。
   本节因此把规则写成「每台门控至少拒绝一条**仪器侧**变异」，并把主张侧目标登记为预期全绿。

### 41 判别力审计推广到全仓库 25 台门控：给每台门控导出「判别地板」，并在一轮里抓出审计仪器自己的三处缺陷

> 承接 §40 / X-77。§40 只推到 Phase IX–XVIII；本节补上 Phase II–VIII 与 `phase2_gate`，
> 并把问题从「这台门控能不能失败」升级为「**多小的机制错误它才看不见**」。
> 仓库文件一律不改、不跑实验（变异只发生在临时副本，R2、R6、owner 第 3 条）。

#### 41.1 方法：尺度梯子，而不是二值判定

一台门控的注册容差规定了它**能看见什么**：Phase V-d 的已知答案对照是 ±0.005 **绝对**，
在它盯的那个 0.06 量级读数上等价于 8e-2 的相对容差——往那里注入 1e-4 的机制错误然后宣布
「门控没有判别力」是错的，宣布的其实是「注入量小于该检查的分辨率」。所以每条 wrap 型变异按梯子
`1e-9, 1e-6, 1e-4`（对注册容差本身较粗的轮次扩到 `1e-3, 1e-2, 1e-1`）由小到大逐档注入，
第一个拒绝的档位就是这台门控的**判别地板**——R7 要求的那个量，只不过这次量的是仪器而不是效应。
若某档的探针读数没变，该档跳过并披露（那是浮点分辨率，不是门控分辨率）。
一条仪器侧变异**预期全盲**时必须事前登记 `expect="blind_all"` 并给出理由；事前没登记的盲即套件失败。

#### 41.2 结果：33 个变异 / 25 台门控 / 23 个模块，套件打印 59/59


读法与要点：

- **12 台门控在梯子第一档 1e-9 就拒绝**（`floor@1e-09`）。这是梯子的第一档而非物理下限：
  1e-9 已经接近 O(1) 量级读数的浮点分辨量级，所以正确的表述是「这些门控的地板 ≤1e-9」，
  不能写成「精度为 1e-9」。
- **9 条单档变异全部拒绝**（`refused`）：§39/§40 的五条遗留目标 + 四条结构性变异
  （尾指标 `m_ge` 偏一位、网格节点数丢掉端点 +1、silent 权重的 k 指数误载 ×2）。
  三条不同的**真实缺陷族**都能在 1 档内被抓，这是本节对 §39「属运气」的说法的替换：
  现在是 25/25 台门控要么拒绝一条仪器侧变异、要么其盲已被事前登记并解释。
- **粗地板是有名字的**：Phase IV 的 CDF 与分位函数都在 **1e-2** 才被拒（C1 的 0.005 绝对容差、
  C2 的 0.05 绝对容差决定）；Phase VII 在 **1e-3**；Phase V-c 在 **1e-4**；Phase V-d 要到 **1e-1**。
  这四条不是缺陷而是**注册口径的后果**——但旧文档从未把「所以我的门控看不见多大的错」写出来，
  本节把它变成每次都能重新导出一行的套件。
- **Phase XV / XVII / XVIII 的地板只到「已注入 1e-4 即拒」**：这三台门控单次运行 51 s / 30 s / 152 s，
  梯子被运行时预算截断为单档（代码里写明），所以它们的地板是上界而非测量值。

### 42 从语法侧导出「哪台门控量了哪个量」：静态仪器覆盖表 v1，10 条缺口全部带登记理由

### 46 把「每一步写入飞书」变成仓库内可以判红的事实：wiki 同步表 v1，并先查出这张表自己与自己打架

**人口与方法**。`governance/build_wiki_sync_map.py` 导出 `governance/wiki_sync_map_v1.json` + `governance/WIKI_SYNC_MAP_v1.md`：

* **节**：`M2A_FINAL_REPORT.md` 中编号 ≥ 31 的步骤节（wiki 通道 2026-10-18 建立之后做的事），共 16 节（本节自身发布后；建表时 15 节）；
* **页**：工坊根台账里带 node_token 的 23 页，按标题是否在发布器的 `PAGES` manifest 里分为治理期 11 页与首批驱动 12 页（后者按条数钉住，多一条少一条都红）；
* **承接**：`节 → node_token` 是**登记表**而不是推导——散文不支持可靠推导（各节点名 X-id 的措辞有五种，且一页可载多节）。登记表写错会以「指向不在台账中的令牌」响亮失败，不会静默；

**校验器 16 条**（`governance/wiki_sync_map_gate.py`，**16/16**）用第二条通路复核：生成器两次跑出同一字节（S1–S3）；**人口由切分文件的另一条路重数**，与生成器的正则扫描一致（S4）；每条承接的令牌确实存在于台账、且台账里读回的父节点与工件一致（S5、S11）；无节未承接、无陈旧承接，并且**工件自己报的"已承接 15"必须等于能从行里数出来的 15**（S6）；11 页治理期页面都被 ≥1 节认领（S7）；12 页首批与 manifest 不重叠（S8）；草稿与工具指纹逐字节相同（S9、S10）；每页台账都记录了成功的读回与标记复核（S12）；人口内各节点名的 X-id 都在负面日志里存在（S13）；以及 S14——把判定面抽成**一个纯函数**，用五种漂移形状（某节没发布 / 承接留给一个已不存在的节 / 治理期页面无人认领 / 草稿发布后被改写 / 首批数目偏离钉住）逐个验证会响，真实数据一个都不响。

**本步抓到的三处**（登记为 X-84）：**(a) 一处会静默放过"某节没发布"的 fail-open**。第一版把「哪些节由哪页承载」只写在**治理期页面**的行里，而 §31 的承接指向的是首批驱动那一页——于是台账行里数出来 14 条承接，`counts` 却按登记表报 15 条，**工件与自己打架**。若校验器只读 `counts`（它确实报了 0 未承接），这一路就是绿的；真正抓住它的是 S6 那句「头条数字必须等于能从行里数出来的条数」。修法不是补一个例外，而是把承接升格为一等行（`claims`），页面行由它派生。
**(b) 一次假警报来自一次性探查脚本的路径基准**：核查时用 `Path('.').parent.parent` 求工坊根，得到 `.` 本身，于是报出「有一份草稿文件不存在」——工件里 10 份草稿的指纹其实全部命中（S9）。同一件事在套件里用 `__file__` 求根就不会发生；写一次性核查脚本时也必须用同一个基准，否则"发现问题"与"制造问题"分不开。 **(c)** 起火控制自己被真实数据追上过一次：`S14` 的「某节没发布」形状原本用字面量 46 当哨兵，§46 一旦真的存在，这条注入就成了空操作（不再产出 unclaimed，控制静默失效），第一次跑出 FAIL 才看见；哨兵改为由人口算出并断言其不在承接表中——**控制用的常数与被测对象的取值范围撞车时，失败方向是静默通过**，与 §40「注入必须是真差别」同族。

**一处顺序上的后果**（值得单独写，因为它改变了循环的走法）：承接的前提是**先有页面才有令牌**，而页面必须先有定稿的草稿才能发布、发布后草稿再改就会撞 S9 的指纹。于是本步实际的顺序与 §42–§45 相反：**先发布（草稿里不写收尾审计的分数，只注明权威读数在终报本节末行）→ 把令牌写进登记表 → 重导工件 → 跑收尾审计取分数 → 把分数填进终报 → 复跑校验器确认工件仍逐字节可复现**。这不是便利问题，而是这张表真正在执行的性质：一条要求"每步都发"的纪律，第一次使得**漏发**在收尾审计里就是红的，代价是把「发布」提前到「提交」之前，并且**发布之后的页面只能追加、不能改写**——本步第三处发现就是这样补进去的，页面里那段"修入"的说明即为此。本步还实测到一次**真实拦截**：我改完守门脚本（数字复核器）而没有立刻重导工件，收尾审计便把这台校验器判红（13/16，红在 S1/S2/S10——工件里钉住的工具指纹与磁盘不符）；重导工件后回绿。这是这张表第一次因真实违规而红，而不是因它设想的情形而红。

**看不见什么（如实写）**：S9/S10 证明的是"字节与我登记时相同"，不证明"发布动作今天仍然成功"；标记与读回字符是台账在发布当时记录的，不是此刻重新 `+fetch` 的（重取要走网络与用户身份，不放进收尾审计）。「节 → 页」是人工登记表，其余数字均从磁盘推导。
